3 варианта развёртывания Mini App

Разница главным образом в том, где живёт SPA и как HTTPS-доступен backend. Везде стек = vanilla JS + HTM (без билда).

TG client
   │
   ├──► open https://pgolitech-lab.github.io/kleinanzeigen-bot/
   │      (GitHub Pages from main:/web-app/)
   │      [HTML + JS load]
   │
   └──► fetch /api/* with initData
          │
          ▼
   cloudflared tunnel  https://xxx.trycloudflare.com
          │            (free, бесплатный random subdomain)
          ▼
   prod 192.168.88.28:8080  (FastAPI, текущий)
          │
          ▼
   SQLite + scheduler.* helpers

A · Same repo + cloudflared (рекомендуемый)

Repo: SPA в /web-app/ того же kleinanzeigen-bot репо. GitHub Pages → settings → folder=/web-app.
Deploy SPA: git push, no build.
Backend HTTPS: cloudflared tunnel (бесплатный, ~30 сек поднять, переживает рестарт через systemd).
Auth: FastAPI middleware валидирует initData через HMAC от bot-token.
Минусы: trycloudflare URL рандомный — если перезапустится без named tunnel, меняется. Решается named tunnel за 5 минут (cf account, без домена).

TG client
   │
   ├──► open https://kleinanzeigen-app.your-domain.tld
   │      (отдельный репо `kleinanzeigen-bot-mini-app`,
   │       GitHub Pages с CNAME на свой домен)
   │
   └──► fetch /api/* with initData
          ▼
   nginx + Let's Encrypt
          ▼
   prod :8080 FastAPI

B · Свой домен + Let's Encrypt

Repo: отдельный репо для SPA. CNAME на купленный домен.
Backend HTTPS: nginx-reverse-proxy + LE-cert на api.your-domain.tld.
Плюсы: красивые URL, стабильные навсегда, профессионально.
Минусы: нужен домен (~$10/год), nginx config, LE renewal, отдельный репо синхронизировать с основным. Серьёзнее по setup-у — 2-3 часа против 30 минут на A.

TG client
   │
   └──► open https://your-domain.tld/ma
          (FastAPI отдаёт static SPA из /web/ma/)
          │
          └──► fetch /api/* (тот же origin)
                 ▼
          FastAPI :8080 (через cloudflared/LE)

C · FastAPI-served (без GitHub Pages)

Repo: SPA в /web/ma/ того же репо, FastAPI mount-ит как StaticFiles.
Backend HTTPS: всё равно нужен (cloudflared / LE).
Плюсы: один origin → CORS не нужен, deploy = restart unit.
Минусы: не выполняет твоё пожелание «оставить на github и пусть TG тянет оттуда». GitHub становится только source-of-truth, не deploy-target.

Моя рекомендация

A · Same repo + cloudflared. Соответствует твоему «git push → live», бесплатно, минимум moving parts. Ниже разберём на нём детали (auth, экраны, синхронизация с ботом). Если в процессе захочется domain — переходим на B без переписывания кода (меняется только URL и cert).
