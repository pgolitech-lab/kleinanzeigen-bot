# Telegram-бот глазами ленивого оператора — разбор и проект нового бота

Дата: 2026-10-20 · ветка `opt/qa` (= main `30fb4f4`) · автор: сессия «тестировщики».
Источники: `modules/telegram_bot.py`, `scheduler.py`, `modules/incoming.py`, `main.py`, `web-app/js/*`,
агрегаты из прод-БД (только счётчики, read-only) и `journalctl` за 7 дней. Ни одного сообщения не отправлено.

Реализует сессия **kab-api** (бот) + **kab-webapp** (новые deep-link маршруты в Mini App).

### 1.3 Путь «пришло письмо → ответил покупателю»

| Шаг | Нажатие | Что видит оператор |
|---|---|---|
| Пуш в Telegram | 1 — открыть чат | немецкий текст письма (перевода нет), список чужих тредов |
| `📋 Открыть MA` | 2 | «Открываю карточку…» → редирект в тред |
| `📨 Отправить` в доке треда | 3 | шит «выбор» (4 кнопки) |
| `📨 Отправить как есть` (черновик уже на языке клиента) | 4 | шит «Подготовка к отправке» (текст + RU) |
| `📨 Отправить` | 5 | финальный шит + языковая проверка (Haiku, ждать) |
| `✅ Отправить` | 6 | готово |

**6 нажатий** при готовом черновике (проверено в headless-прогоне, `docs/qa/baseline.md`), **7–8** при переводе/правке.
В боте ответить нельзя совсем — только открыть Mini App.

### 1.4 Что только в Mini App
Всё содержательное: перевод письма, черновик, отправка, правка, «Продано», «Ждать», автопилот, история клиента, продажи.
В боте остались только: открыть MA, «Прочитал», `/tasks` со списком, «🗑 закрыть тред» из `/tasks`.

### 1.5 Внешние экраны (Fold 8 Ultra внешний ≈ 412 px, Flip 5 Flex Window ≈ 306×318 px)
- Уведомление №1 занимает 12–15 строк: на Flex Window видна только шапка и начало немецкого текста; кнопки — за прокруткой.
- В `/tasks` подписи кнопок по 60 символов, на 306 px видно ~18 — строки неотличимы («⏳ Klaus M. · Hallo, ich in…»),
  а маленькая `🗑` вплотную справа — риск закрыть тред случайным тапом (и без подтверждения).
- Mini App на Flex Window открывается только если Telegram разрешён на внешнем экране; высота 318 px — шапка Telegram
  + шапка MA + таб-бар съедают ~55 % экрана (см. `docs/qa/baseline.md`, устройство `flip5-flex`).

## 2. Проблемы

### P1 — теряем покупателя / деньги / безопасность
1. **Нет проверки отправителя в поллере** (`start_callback_poller`, `telegram_bot.py:554–620`). Любой пользователь Telegram,
   написавший боту `/tasks`, получает список активных переговоров (имена покупателей, начала писем, объявления), а callback
   `close_<thread_id>` закрывает тред **без проверки, кто нажал** (`db.close_thread`). Нужно: игнорировать всё, что не из
   `config.telegram_authorized_ids()`.
2. **Письмо покупателя показано по-немецки**, хотя перевод `ru_client` уже есть к моменту уведомления
   (`_build_review_text` берёт `de_client`). Оператор, не знающий немецкого, не понимает из пуша, срочно ли это.
3. **Уведомления не обновляются после ответа**: `broadcast_after_external_action` / `broadcast_thread_state` — заглушки.
   Через час в чате 9 «🆕 Новое обращение» с живыми кнопками, и непонятно, на какие уже ответил второй оператор → двойные
   ответы или пропуски.
4. **Открыл из уведомления — потерял текст.** Mini App не подключает нативную `Telegram.WebApp.BackButton` (есть только «←»
   в шапке) и не включает `enableClosingConfirmation` → системный «назад» Android / свайп вниз закрывает MA целиком.
   Правка черновика при «←» тоже теряется молча (проверено в прогоне: `unsaved.kept = false`, предупреждения нет).
   Петли «Назад» после deep-link `review_<id>` в headless-прогоне **нет** (тред → «←» → Входящие).
5. **Алерты об ошибках не приходят вообще** (нашёл агент `qa`): `monitor_errors_job` читает `journalctl -p warning`, а все
   строки Python-логов пишутся в journald с priority 6 (info) → 0 строк, «no issues» всегда. За 7 дней в журнале 36 ERROR
   (DNS, `AUTHENTICATIONFAILED` IMAP) — ни одного алерта. На этом же джобе держится сторож `polluted_incoming`.

### P2 — путает и шумит
6. Один пуш на **каждое письмо**, не на тред; второй оператор получает те же пуши (2 копии на всё).
7. В каждом уведомлении блок «📋 Ещё активных: N» + 5 строк чужих тредов на немецком — повторяется в каждом пуше, тянет
   сообщение до 15 строк, на внешних экранах выталкивает кнопки.
8. `👁 Прочитал` — 0 нажатий за неделю; лишняя кнопка, которая ещё и перерисовывает все копии.
9. `⚙️`-пуш при каждом рестарте (5 за неделю) — `clear_reply_keyboards` нужен был один раз в июне.
10. Технический дайджест ошибок (сигнатуры логов, `modules/scout.py`) идёт в тот же чат, что и покупатели.
11. Сводка 09:00: «inquiries», «skip», «💸 потрачено $0.0000» (LLM теперь по подписке — цифра бессмысленна);
    нет главного — **сколько ждут ответа сейчас** и продаж.
12. Напоминание пишет `Клиент молчит 1.0 дн.` — это порог из настроек, а не реальное время молчания; по одному пушу на тред,
    в любое время (джоб ежечасный).
13. Menu Button открывает **Обзор**, а не **Входящие** — лишний тап к главной задаче.
14. `🗑` в `/tasks` закрывает тред сразу, без подтверждения и без «Отменить».
15. Тихих часов нет: пуши в 23:00, автопилот в notify-режиме пингует на каждый авто-ответ.
16. Номера `#1234` в каждом заголовке — внутренний id, оператору ничего не говорит.

### P3 — мелочи
17. `📭 Inquiry на проданное`: имя отправителя не экранируется (`incoming.py:510`) — `<` в имени ломает parse_mode=HTML
    и уведомление молча теряется; слово «Inquiry».
18. Автопилот: «floor», «Sonnet решил что нужно остановиться» — жаргон.
19. Подписи кнопок разные для одного действия: `📋 Открыть MA` / `📋 Открыть в MA` / `📋 Открыть тред`.
20. `setMyCommands` — только `/tasks` с описанием «Список висячих задач».
21. `sendBeacon` в `thread.js:912` бьёт относительным путём `/api/ma/…/release-beacon` — уходит на GitHub Pages, а не на
    бэкенд; лок после закрытия MA висит 5 мин (к боту относится косвенно: второй оператор открывает из пуша занятую карточку).

## 3. Проект нового бота

### 3.1 Принципы
- **Одна живая карточка на тред.** Новое письмо в треде, где уже висит неотвеченная карточка, — правка той же карточки
  (`editMessageText`) + короткий пуш только если прошло > 10 мин с прошлого. После ответа/«Ждать»/«Продано» (из MA, любым
  оператором) — карточка сворачивается в одну строку без кнопок. Хранение — уже есть `card_dispatches`
  (ключ: `gmail_thread_id` вместо `message_id`).
- **По-русски.** В пуше — перевод письма (`ru_client`), немецкий не показываем.
- **Первая строка ≤ 30 символов, ≤ 6 строк всего, ≤ 2 кнопки в ряд, подписи ≤ 14 символов** — влезает на Flex Window 306 px.
- **Ответ в 2 нажатия:** кнопка карточки открывает MA сразу на финальном шаге отправки готового черновика
  (языковой guard остаётся в MA — бот сам ничего покупателю не шлёт).
- **Только авторизованные:** каждый update от chat_id не из `telegram_authorized_ids()` — молча игнорировать.
- **Тихие часы** 22:00–08:00 (Берлин, настройки `tg_quiet_from`/`tg_quiet_to`): всё с `disable_notification: true`,
  кроме срочного (см. 3.4); в 08:00 одна утренняя сводка.
- **Тех.сообщения — отдельно:** дайджест ошибок, scout-поломка, рестарты — в `telegram_admin_chat_id` (новая настройка;
  пусто → не слать вообще), не в чат операторов.

### 3.2 Сообщения (тексты-образцы)

**A. Новое письмо / ответ покупателя** (одна карточка на тред, звук; в тихие часы — без звука)
```
💬 Klaus M. · Ersatzteile Nord
Rückbank Peugeot · 450 €
«Скамья ещё есть? Последняя цена 300?»
Черновик: «Да, есть. 300 мало — 400 можно.»
[✅ Ответить]  [💬 Переписка]
```
- `✅ Ответить` → `web_app` `send_<msg_id>` (MA открывает тред и сразу финальный шит отправки черновика: текст клиенту,
  RU-перевод, языковая проверка, кнопка «Отправить»). Если черновика нет (`new`, ещё генерится) — кнопка `✍️ Написать`
  → `compose_<thread_id>`.
- `💬 Переписка` → `thread_<thread_id>`.
- Новое письмо в том же треде до ответа: текст карточки дополняется строкой `+1 новое · 12:40 «…»`, кнопки те же.
- Автопилот активен: карточку не шлём (см. D).

**A′. После действия** (любой оператор, из MA — реализовать `broadcast_thread_state` по-настоящему):
```
✅ Klaus M. · ответил Pg 12:52
```
```
✋ Anna_K · ждём клиента (Pg)
```
```
💰 Piotr · продано 250 € (Pg)
```
Без кнопок; при следующем письме — новая карточка A.

**B. Пачка писем** (за 3 мин пришло ≥ 3 новых треда — одна карточка вместо трёх пушей)
```
📥 Ждут ответа: 3
• Klaus M. — «Ещё есть? 300?»
• Anna_K — «Фото снизу?»
• Piotr — «Доставка в Польшу?»
[Klaus] [Anna_K] [Piotr]
[📥 Все входящие]
```
Имена-кнопки → `send_<msg_id>`; `📥 Все входящие` → `inbox`.

**C. Напоминание** — одно в день, 10:00, пачкой (вместо пуша на каждый тред в любое время)
```
⏰ Молчат больше суток: 2
• M.Yilmaz · Vito — 2 дн.
• B.ST · Trafic — 4 дн.
[M.Yilmaz] [B.ST]
[🤫 Не напоминать сегодня]
```
Имя → `thread_<id>` (тред с открытым «Написать»); реальное число дней от последнего исходящего.

**D. Автопилот** — одна живая карточка на тред, правится при каждом авто-ответе **без звука**:
```
🤖 Автопилот · Klaus M.
Ответов 3 из 20 · минимум 300 €
Последний: «400 € ist mein letzter Preis»
[🛑 Стоп]  [💬 Переписка]
```
Звук — только на остановку, требующую человека:
```
🎯 Klaus M. готов купить — автопилот стоп
«Kann ich morgen abholen?»
[✅ Ответить]  [💬 Переписка]
```
`🛑 Стоп` — callback (с проверкой авторизации) → `stop_thread_autopilot(…, "manual")` → карточка правится в «остановлен (Pg)».
Уведомление «включён» — только **другим** операторам, не тому, кто включил.

**E. Утренняя сводка 08:00** (замена «Сводки за вчера»)
```
☀️ Доброе утро
Ждут ответа: 3 · ждём клиентов: 5
Вчера: 9 писем, ответили 8, продано 1 (330 €)
Рынок: +2 машины, +6 запчастей
[📥 Входящие]  [📊 Обзор]
```
Если ждут 0 и вчера пусто — не слать. Ночные письма (тихие часы) учтены в «Ждут ответа».

**F. Письмо по проданному объявлению** — без звука, одна строка (или только в сводке E):
```
📭 Trafic уже продан — письмо от B.ST пропущено
[💬 Переписка]
```

**G. Рынок** — без звука, не чаще 1 раза в день (или только строка в сводке E):
```
🔎 Рынок: +2 машины, +6 запчастей
[🔎 Открыть]
```
Список ссылок — только в MA.

**H. Тех.** (в `telegram_admin_chat_id`): дайджест ошибок, scout-0, «бот перезапущен» — как сейчас, но не операторам.
`clear_reply_keyboards` — убрать из `main.py` (или выполнить один раз по флагу в settings).

### 3.3 Команды и меню
| Команда | Что делает |

### 3.5 Deep-link в Mini App (что добавить в `web-app`, сессия kab-webapp)
| start_param | Экран | Сейчас |
|---|---|---|
| `inbox` | Входящие | есть как `pipeline` |
| `thread_<thread_id>` | тред | есть |
| `send_<msg_id>` | тред + сразу финальный шит отправки черновика (этап 3 send-флоу: текст, RU-перевод, lang-check) | **нет** |
| `compose_<thread_id>` | тред + открыт «Написать» | **нет** |

### 3.7 Приёмка (проверит QA после слияния)
1. Сообщение `/tasks` / `/inbox` от неавторизованного chat_id — нет ответа, в журнале warning; callback `close_…`/`stop…` от
   него — без эффекта (unit-тест на поллер с подменённым `_http_post_single`).
2. 3 письма в одном треде за 5 мин → 1 сообщение в чате (правится), 1 пуш со звуком.
3. Ответ из MA → все копии карточки треда у всех операторов свернулись в `✅ … ответил …` (по `card_dispatches`).
4. Текст карточки ≤ 6 строк, первая ≤ 30 символов, нет немецкого письма покупателя (кроме цитаты автопилота).
5. `send_<id>` → MA открыт на финальном шаге; «Назад» → тред → «Назад» → Входящие (без петли); системный «назад» на Android
   не закрывает MA с несохранённым текстом молча.
6. 22:00–08:00 — все `sendMessage` с `disable_notification: true`, кроме D-срочных.
7. Рестарт сервиса — ни одного сообщения операторам.
8. Каждая отправка в Telegram пишет в журнал строку `tg sent: <kind> chat=<id> thread=<id>` (чтобы QA мог считать шум).
9. Строка `ERROR` в журнале сервиса → через ≤ 1 ч дайджест в `telegram_admin_chat_id` (проверка `monitor_errors_job` на
   тестовой строке; сейчас фильтр `-p warning` не видит ни одной).
