# C «Командный центр торговца»

**Питч.** Биржевой терминал для сделок: каждый тред — это котировка. Сверху «пульс» (ждут нас,
медиана скорости ответа, выручка сегодня/за месяц со спарклайном), под ним цветные чипы пяти
аккаунтов-фильтров. В очереди у каждой сделки «термометр торга»: шкала от floor до цены
объявления, на ней предложение клиента (жёлтый треугольник), наше последнее (синяя точка) и
красная черта floor, плюс язык клиента, таймер ожидания (зелёный → янтарный → красный) и шанс
сделки в процентах. Оператор за секунду видит, кто горит и где есть деньги. В треде «пульт ответа»:
тон и цена — одним тапом по чипу («ИИ», «Держим цену», «−5 %», «До floor», «Вежливо отказать»;
на каждом чипе сразу видна цена), черновик на языке клиента, RU-зеркало, бейдж «DE ✓» и большая
«Отправить». Рядом лежит панель сделки (термометр с легендой, разрыв торга, сколько клиенту до floor,
скидка черновика) и клиента (покупки, средний торг, заметка). Цифры моноширинные, сетка
табличная. Тема «бумажный терминал» (светлая) и «ночной трейдинг» (тёмная).

## Раскладка по устройствам
- **Fold, внутренний экран (820–910 px)**: три колонки: очередь | тред с пультом | сделка + клиент.
  Пульс и вкладки (Сделки / Клиент / Продажи) — в верхней строке. Продажи занимают обе правые колонки.
- **Узкие экраны (280–412 px)**: одна колонка, нижний таб-бар. В треде таб-бар скрыт, чтобы не
  перекрывать пульт. Сделка и клиент открываются листами снизу: кнопки «Сделка»/«Клиент» в шапке
  или тап по полосе термометра. Лист закрывается свайпом вниз, тапом по фону или кнопкой ×.
  На ширине ≤ 330 px подписи кнопок шапки и этапы 1–2 скрыты, термометр уходит на отдельную строку.
- **Flip Flex Window 306×340 — «пейджер»**: следующая ожидающая сделка (n/N), последнее сообщение
  клиента по-русски, RU-зеркало нашего ответа, клиент → наш ответ, «Отправить DE ✓», «Назад»/«Далее»,
  свайп влево/вправо листает. Для `client`/`sales` показаны мини-карточки.

## Текущие функции и новые данные (дополнение владельца)
- **Выбор нескольких тредов**: кнопка-галочка рядом с фильтром включает режим выбора, снизу
  появляется панель «Закрепить / Жду / Пропуст.» со счётчиком выбранных.
- **Закрепление**: закреплённые треды стоят первыми в очереди (значок-кнопка). Переключается из
  панели сделки или пачкой.
- **«Жду»**: тред уходит в «Ждём» с пометкой «жду до завтра 10:00». В треде под лентой появляется
  полоса состояния. Повторное нажатие («Не ждать») возвращает тред в «Ждут нас».
- **Ручная продажа**: «+ Продажа» на экране продаж открывает лист с формой (объявление, цена, аккаунт).
  «Продано» в панели сделки записывает продажу по цене черновика.
- **Найденные продажи**: панель на экране продаж, у каждой находки есть причина («клиент написал
  „Abgeholt“», «объявление снято») и кнопки «Подтвердить» / «Отклонить». Подтверждение сразу меняет KPI.
- **Теги** (добавить / убрать по тапу) и **заметка о клиенте** — в панелях сделки и клиента.
- **Досье клиента**: короткая лента «дата — о чём писал, какие цены» в панели клиента и в профиле.
- **«Возможно, тот же покупатель»**: янтарная плашка вверху ленты треда (тап открывает клиента)
  и блок в досье: другое имя и аккаунт, почему похож.
- **Уроки**: в пульте ответа счётчик «уроки 3» раскрывает правки оператора, которые ИИ учёл
  (было → стало, правило).
- **«из приложения»** — у сообщений, пришедших через сайт или приложение Kleinanzeigen;
  **«запоздалое»** — у писем, пришедших с опозданием (в треде с пояснением: когда дошло). Обе пометки
  видны и в строках очереди.
Мок для всего этого лежит в `FEAT` в `app.js`.

## Инвариант языка
Бейдж языка пересчитывается при каждом вводе. Кириллица для не-русского клиента → рамка краснеет,
бейдж «RU ≠ DE», «Отправить» выключена. Разблокировать можно только галочкой «Разрешаю отправить
текст не на языке клиента». Кнопка ✎ имитирует `/edit-ru` (переводит русский текст на язык клиента).
Этапы 1–2 (выбор, подготовка) показаны как пройденные: прототип сразу открывает этап 3.

## Файлы
- `index.html` — каркас (пульс, 3 колонки, таб-бар, пейджер, лист, тост).
- `style.css` — токены от `--tg-theme-*` с фолбэком на пресеты, раскладки `mode-narrow / mode-wide / mode-pager`.
- `app.js` — состояние, рендер, жесты, View Transitions. Локальные дополнения к моку лежат в `EXTRA`
  (наше последнее предложение, минуты ожидания) и `TPL` (шаблоны тонов на DE/PL/NL/TR + RU).
- `shots/` — скриншоты `shoot.py` (6 устройств × 4 экрана, светлая тема на flip-main и fold-inner-land).

URL: `?screen=inbox|thread|client|sales`, `?theme=dark|light`. Режим выбирается по размеру окна:
пейджер при ≤ 360×460, три колонки при ширине ≥ 760.

## Ограничения и риски для реального MA
- Чипы тона в MA — это вызовы `/instruction` или `/regenerate` к LLM (секунды задержки и деньги),
  а не мгновенные шаблоны. Нужен спиннер на чипе и кэш вариантов по треду.
- «Шанс сделки», «наше последнее» и floor в списке берутся из `deal_brief_json` и `thread_autopilot`.
  Для pipeline-эндпоинта их надо отдавать пачкой, иначе будет N+1.
- Экран «Клиент» в таб-баре показывает клиента текущего треда. В реальном MA там должен быть список
  CRM с поиском.
- Галочка «Разрешаю…» — только клиентская логика. Серверный 409-guard в `/send` по-прежнему обязателен,
  как и Haiku lang-check (в прототипе работает только эвристика по кириллице).
- Шрифт 18 px с моноширинными цифрами занимает много места: на 280 px лента треда при открытом пульте
  показывает 1–2 сообщения. Черновик ограничен по высоте и прокручивается.
- `color-mix()`, `-webkit-line-clamp` и View Transitions нужны в свежем WebView (Telegram Android/Desktop
  их поддерживают; без View Transitions работает CSS-фолбэк).
